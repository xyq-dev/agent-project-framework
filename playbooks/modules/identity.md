# 登录身份实施蓝图

通用设计输入，Runtime tests=NOT_RUN。实施风险 high，需项目设计与独立安全复核。见 [实施方案](../../framework/MODULE_ADOPTION_PLAN.md)。

## 采用前确认

确认使用者、客户端类型、认证方式、已有身份服务、账号恢复/绑定需求、会话策略及是否涉及多租户。邮箱、手机号、微信/OIDC 等方式按项目选择，不默认全部实现。

## 最小范围与契约

- 身份验证、建立会话、获取当前可信主体、退出/失效，以及项目需要的恢复路径。
- 主体使用稳定内部 ID；第三方主体映射包含来源/发行方及其标识，不能用昵称或未验证邮箱随意合并账号。
- 身份模块拥有认证映射与会话；头像、简介等资料归用户/媒体能力，业务角色归权限策略。
- 先选择成熟身份服务或经过维护的协议组件。项目决定会话存储、刷新、撤销与客户端保存方式；不把短期令牌过期等同于即时撤销。
- Cookie、Bearer、小程序登录等分别评审其传输与攻击面；按选定协议验证回调上下文，不能把前端返回的用户 ID 视为认证凭据。

限制认证尝试、使用适当的统一失败响应，敏感操作按项目规则再次验证；参考 [OWASP Authentication](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html)。

## 实施任务

| ID | 交付 | 验收 |
| --- | --- | --- |
| IDN-001 | 认证方式、主体映射、会话与恢复设计 | 覆盖退出、失效、禁用和账号冲突 |
| IDN-002 | 选定服务/协议适配和主体端口 | 服务端验证可信身份，普通资料不参与认证 |
| IDN-003 | 会话策略和异常处理 | 生命周期与项目承诺一致，不泄漏凭据 |
| IDN-004 | 集成测试与独立复核 | 正常认证、失败、重放和退出后的行为有证据 |

## 必须验证

无效/过期/重复凭据、用户枚举风险、认证限流、账号禁用、会话固定/撤销策略、并发刷新、第三方标识冲突；账号绑定与恢复额外验证所有权。测试使用隔离身份/测试环境。

## 完成条件

支持的认证方式和未支持方式明确；登录、退出、过期与授权消费端有一致证据。验证码若为前置，提前接入必要通知能力或使用身份服务，避免循环依赖。
