# 通知实施蓝图

本页是项目设计输入。一般业务通知建议风险：medium；验证码、账户恢复或敏感内容升为 high 并独立审查；Runtime tests = NOT_RUN。先读[总实施方案](../../framework/MODULE_ADOPTION_PLAN.md)。

## 采用前确认

- 按需求选择站内、邮件、短信或其他渠道；确定模板、语言、收件人来源、许可/订阅规则、发送频率和费用限额。
- 区分营销、事务通知和认证验证码。验证码生命周期与校验归 Identity 或宿主认证服务，通知模块只承担受控投递。
- 收件人与业务事件由宿主提供受信任引用，不强制依赖登录模块；需要匿名通知或验证码时可提前实施。

## 最小范围与契约

- 发送意图包含业务事件引用、幂等键、模板及版本、经过校验的参数、收件人引用、渠道、有效期限与关联 ID。
- 模板按输出渠道正确转义，限制参数长度、敏感内容和链接来源；凭证及完整敏感内容不进入日志。
- 明确 queued / accepted / delivered / failed / expired 等状态的服务商证据。服务商 accepted 不能直接标记收件人已收到或已阅读。
- 对重复消息、限流、暂时错误、永久拒绝、取消和过期设置有界重试与去重保留期。超时可能已发送，必须记录未知结果与重复投递风险，不能承诺无依据的 exactly-once。
- 业务提交与发送意图的可靠衔接由项目选择事务队列、outbox 或可接受的尽力投递；通知失败不能擅自回滚已完成的付款等业务状态。

## 实施任务

| 任务 | 交付与前置条件 |
| --- | --- |
| NTF-001 | 确定渠道、模板、接收策略、状态证据和失败容忍度；认证通知先评审敏感边界 |
| NTF-002 | 实现发送意图校验、模板渲染、去重策略与宿主调用接口 |
| NTF-003 | 接入选定服务商和必要的队列/重试；有回执时校验来源并更新状态 |
| NTF-004 | 完成故障及隐私测试；记录费用、限流、暂停与恢复方法 |

## 必须验证

- 重复意图、并发提交、服务商超时、限流、永久拒绝、回执乱序和重启后的状态恢复。
- 接收者替换、模板参数注入、敏感数据泄漏、过期验证码投递及退订策略。
- 重试有截止时间和次数限制；失效消息不能无限发送，投递状态与真实证据对应。
- 模拟发送、服务商测试环境和真实收件人发送分开记录。本蓝图不授权发送真实消息。

## 完成条件

项目选定渠道通过实际适配器测试，失败/未知结果可追踪，接收与隐私策略有验证。若只运行 Fake 渠道，交付状态必须保留真实投递未验证。
