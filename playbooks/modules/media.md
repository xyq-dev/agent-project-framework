# 文件与媒体实施蓝图

本页是项目设计输入。建议风险：high；项目独立审查尚未执行；Runtime tests = NOT_RUN。先读[总实施方案](../../framework/MODULE_ADOPTION_PLAN.md)。实际新增数据库表或迁移按项目风险规则单独评审。

## 采用前确认

- 选择实际需要的文件类型、大小、下载方式、预览/转码能力，以及用户、租户与业务资源的归属关系。
- 明确保留、删除、软删除、失败重试和孤立对象清理期限。区分原始文件、派生版本及各自的存储开销。
- Storage 提供对象操作，Authorization 提供访问判定；媒体模块持有资产记录与处理状态，不另建一套登录系统。

## 最小范围与契约

- 资产记录包含不可预测的业务 ID、对象引用、所有者/租户、类型与大小、版本、创建时间和状态；状态可裁剪为 pending → uploaded → processing → ready，另含 failed / deleting / deleted。
- 客户端申请上传后，仅服务端确认对象存在、元数据及约束满足，才能推进资产状态。对象上传成功不等于资产已可公开读取。
- 检查不只依赖扩展名或 Content-Type。按项目允许的类型选择实际解码、内容检查或隔离流程，并限制像素、时长、解压比、CPU/内存和处理超时；主动内容格式需要专门策略。[OWASP 文件上传指南](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html)
- 预览、下载、列表和派生文件均执行资源授权；对需保护的文件使用受控响应或短期链接，明确链接撤销限制。
- 上传、处理和删除允许重复请求或消息；用版本、幂等标识和状态条件避免旧任务覆盖新版本。数据库与对象存储的部分成功需要补偿及可审计的清理路径。
- 外部 URL 导入为可选能力；启用时单独设计请求目标、重定向、网络边界与资源预算，不能直接抓取用户任意 URL。

## 实施任务

| 任务 | 交付与前置条件 |
| --- | --- |
| MED-001 | 明确资产模型、归属、状态流转、允许类型、存储与数据库变更计划 |
| MED-002 | 实现申请上传、服务端核验、资产查询和受控下载，串联 Storage 与权限接口 |
| MED-003 | 仅对已选需求实现处理、重试、删除补偿和孤立对象清理 |
| MED-004 | 完成跨模块测试、恶意文件/越权检查和独立审查，记录容量与恢复边界 |

## 必须验证

- 跨用户/租户访问、猜测资产 ID、旧版本、列表及派生文件不能绕过权限。
- 假扩展名、伪造类型、空文件、超限、解码失败、压缩/像素膨胀和超时有明确拒绝或隔离结果。
- 伪造完成回调、未上传对象、重复完成、任务乱序、重复处理、处理中删除和存储失败不会产生错误的 ready 状态。
- 记录创建成功但上传失败、对象删除成功但状态提交失败等部分成功可恢复；清理范围受项目与资产归属限制。
- 若启用外部 URL 导入，验证受限目标及重定向，测试不能接触生产内网。

## 完成条件

项目选定文件类型从上传到授权访问、处理、删除形成可追踪流程；已选安全限制有真实测试证据。未实现的转码、病毒扫描或导入功能明确列为未支持，不用空适配器标记完成。
