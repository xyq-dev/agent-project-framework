# OSS 适配器实施蓝图

本页是项目设计输入。建议风险：high；项目独立审查尚未执行；Runtime tests = NOT_RUN。先读[总实施方案](../../framework/MODULE_ADOPTION_PLAN.md)。本蓝图的 OSS 指阿里云 OSS，是 Storage 的服务商适配器；本目录是指南；可选参考代码已位于 APF Storage TypeScript 包（ali-oss 6.23.0），仅通过离线 SDK/loopback 测试，独立离线源码/安全审查已正式通过，真实云及全模块 Test/Security/Acceptance 待完成。其他服务商另行选择适配器。

## 采用前确认

- 确定服务商、区域、Bucket、项目专用前缀、对象访问方式、容量与费用边界；记录实际 SDK 版本及官方接口依据。
- 由项目明确对象归属、上传/下载授权、覆盖规则、可接受的链接有效期和即时撤销需求。默认私有对象；公开资源必须有项目明确的访问策略。
- 凭证来自宿主受控配置或凭证服务。云资源创建、IAM 调整和真实对象读写需在项目任务中明确授权范围。

## 最小范围与契约

- 实现选定的 Storage 操作、错误映射和能力矩阵；原子条件写入、分页、流、签名链接分别用所选服务商的能力与验证结果声明支持情况。
- 服务端先校验当前用户与对象权限，再用官方 SDK 生成限定对象、方法、期限及必要请求条件的凭据或链接；客户端不得自行指定任意 Bucket、前缀或扩大权限。
- 预签名链接本身持有访问能力；实际有效期受签名期限和临时凭证期限共同限制。应用退出登录不等于已有链接失效；需要即时撤销时，应另行设计受控代理或可撤销的访问机制。[OSS 预签名 URL 官方说明](https://www.alibabacloud.com/help/en/oss/user-guide/upload-files-using-presigned-urls)
- 上传限制分为“协议可强制的条件”和“上传后的服务端检查”。不能只信任客户端大小、Content-Type 或完成回调；需要内容检查时先进入隔离状态，确认对象与元数据后才开放业务使用。
- 日志不记录凭证、完整签名链接或未经筛选的服务商错误。网络超时后的写入结果可能未知，应查询或按已设计的幂等机制处理，不能盲目重试覆盖操作。

## 实施任务

| 任务 | 交付与前置条件 |
| --- | --- |
| OSS-001 | 明确服务商能力、授权矩阵、对象前缀、凭证范围和链接撤销策略；先完成项目设计审查 |
| OSS-002 | 实现选定 SDK 适配器、受控配置、错误映射和实际支持的 Storage 契约 |
| OSS-003 | 接入上传/下载授权、签名条件和服务端上传完成核验；与资产状态联调 |
| OSS-004 | 完成故障测试、获准的隔离前缀集成测试和独立安全审查，记录清理与回滚方式 |

## 必须验证

- 无权限、跨用户/租户、篡改对象 key、扩大前缀、替换方法或签名约束头均不能获得额外权限。
- 链接过期、临时凭证先过期、凭证轮换和退出登录后的既有链接行为，符合已声明的访问策略。
- 覆盖冲突、AccessDenied、对象不存在、分页边界、限流、断流、未知写入结果与 SDK 错误映射。
- 上传条件实际生效；伪造上传完成、错误类型/大小或未通过检查的对象不能成为可用资产。
- Fake SDK 测试与真实服务商测试分别记录。真实测试只操作获准的独立前缀，不修改现有生产 Bucket 策略或清理其他对象。

## 完成条件

项目中选定的 OSS 操作通过契约和集成测试，凭证与授权审查有独立证据，错误及未知结果有可恢复路径。缺少真实服务商验证时明确记录未验证能力，不能据此宣布 OSS 已可生产使用。
