# 支付实施蓝图

本页是项目设计输入。建议风险：critical；项目设计、安全、数据变更及上线审查尚未执行；Runtime tests = NOT_RUN。先读[总实施方案](../../framework/MODULE_ADOPTION_PLAN.md)。本任务包没有授权真实扣款、退款、结算或生产配置变更。

## 采用前确认

- 宿主先提供可信订单、服务端金额与币种、购买者及权益发放契约；支付模块维护支付尝试、服务商交易引用和退款记录。
- 选择服务商、商户、测试环境与实际 SDK 版本，明确支付方式、取消、超时、部分退款、手续费和对账范围。
- 资金、订单及数据库一致性必须由项目独立评审；业务定价、会计账本或订阅计费不因采用本蓝图自动包含。

## 最小范围与契约

- 创建支付和退款前，服务端校验调用权限、订单归属、当前状态、金额及币种；客户端跳转结果仅用于展示，不作为到账凭据。
- 使用选定服务商规定的签名校验方法核实回调，必要时按官方方式保留原始请求体。核对商户、订单、交易引用、金额、币种及权威支付状态后才更新业务；不能只验证“签名正确”。这些验证针对回调伪造、参数篡改和重复通知风险。[OWASP 支付网关集成指南](https://cheatsheetseries.owasp.org/cheatsheets/Third_Party_Payment_Gateway_Integration_Cheat_Sheet.html)
- 对支付请求、事件和退款采用明确作用域及保留期的幂等标识；同一标识但不同金额或参数必须拒绝。状态转移用实际数据库的事务/条件更新保护，处理并发与乱序，避免重复发放权益。
- 外部扣款成功但本地超时属于未知结果；按服务商查询、回调与对账流程确认，不能直接当作失败再次扣款。
- 退款校验原交易、可退额度、已退/处理中金额及操作者权限；并发部分退款不能超过允许总额。业务订单和支付状态分别记录，不由通知模块判定成功。
- 明确事务提交、消息投递、权益发放与补偿的边界；outbox 等方案依项目实际数据平台决定，不凭文档声称跨系统 exactly-once。需要迁移时另交迁移、备份、验证和回滚任务。

## 实施任务

| 任务 | 交付与前置条件 |
| --- | --- |
| PAY-001 | 明确订单/金额来源、状态机、退款权限、数据设计、服务商契约和风险；独立审查通过后实施 |
| PAY-002 | 实现受控支付请求、服务商适配器、回调校验与幂等状态更新 |
| PAY-003 | 按选定范围实现查询、退款、对账、补偿及权益衔接，保留人工处理入口 |
| PAY-004 | 完成服务商测试环境验证、并发故障测试和独立安全/一致性审查，提交上线及回滚证据 |

## 必须验证

- 错误或缺失签名、错误商户/订单/金额/币种、伪造客户端成功返回、重复与乱序回调。
- 同幂等键不同参数、并发支付请求、支付成功后连接丢失、回调早于本地响应、重启恢复。
- 重复/并发退款、部分退款累计上限、无权退款、未知退款结果与已撤销权限。
- 服务商成功但本地提交失败、通知失败、权益发放失败、对账不一致均有可观测和可恢复结果。
- Mock 与服务商测试环境证据分别列出。上线前另确认生产商户、密钥、监控及回滚授权；测试环境通过不等于允许真实交易。

## 完成条件

只有项目选定支付范围通过服务商测试、并发一致性验证及独立审查，才能进入上线验收。未完成退款、对账或恢复能力需明确限制上线场景；本通用蓝图不构成任何项目的支付 Gate 通过证明。
