# 项目计划与开发记录

这是新项目的填写模板，当前没有任何已批准需求或通过的门禁。先填写有事实支持的部分，未知项写待确认；随着内容增长再拆专题文档并保留链接。

## 1. 立项与首版范围

- 问题、目标用户、核心使用场景：待确认。
- 首版目标与成功指标：待确认。
- 时间、成本、技术、平台和数据约束：待确认。
- 本次不做的事项：待确认。
- owner、分析者、验收负责人：待确认。

需求记录格式：`REQ-ID / 用户问题 / 业务规则 / 优先级 / 可验证验收 / Issue / 状态`。每条规则记录来源；推测不得写成已确认事实。

## 2. 阶段裁剪

依据 `framework/WORKFLOW.md` 与 `framework/PROJECT_PLAYBOOK.md` 填写每个阶段的 mode、reason、owner、evidence。机器状态以 `.agent-project/workflow.yaml` 为准，本节记录裁剪理由与批准记录。

默认所有阶段 pending。无 UI、数据库、外部 API、部署等对象时，逐项说明 N/A；适用但要跳过时记录理由、风险与批准者。不能把旧项目的 complete 状态复制过来。

## 3. 产品、UX 与 UI

- 角色、主要功能、关键业务状态和异常规则。
- 主要用户路径；空、加载、失败、无权限和成功状态。
- 有界面时记录页面清单、设计文件链接及版本、组件/响应式约定、实现验收截图要求。
- 无界面时给出适用性结论，不编造页面。

当前：待需求确认后填写。

## 4. 架构与能力选择

记录技术栈及理由、模块/服务边界、外部依赖、数据流、可用性和性能目标。架构决策格式：`ADR-ID / 问题 / 选择 / 理由 / 影响 / reviewer / evidence`。

| 能力 | 决定 | 来源/版本 | 风险与验证要求 |
| --- | --- | --- | --- |
| 身份/登录 | 待定 | 待定 | 采用时审查身份和会话边界 |
| 角色/权限 | 待定 | 待定 | 采用时验证服务端访问控制 |
| 文件存储/OSS | 待定 | 待定 | 采用时验证真实适配器和访问范围 |
| 配置/审计 | 待定 | 待定 | 采用时定义秘密配置与事件边界 |
| 媒体处理 | 待定 | 待定 | 采用时定义处理任务、格式和失败恢复 |
| 通知 | 待定 | 待定 | 采用时定义渠道、触发、重试和去重 |
| 支付/退款 | 待定 | 待定 | 采用时走 critical 风险路径 |
| 项目特有业务 | 待定 | 待定 | 按实际影响评估 |

“采用”后补 owner、理由、验收和实际实现来源；不需要的写不适用，暂不做的写延后。APF 规范本身不提供上述能力的已完成代码。

## 5. 数据与 API

- 数据：实体、归属、约束、关系、索引、生命周期；涉及变更时记录 Migration 与恢复方案。
- API：操作、输入、输出、错误、权限、分页、幂等/并发要求、版本兼容和消费方。
- 适用性与审查结论：待定；不适用时说明原因。

## 6. 可执行任务

每个实际任务建立 Issue，记录：`TASK-ID / REQ-ID / 前置依赖 / owner / 风险 / 工作目录与分支 / 目标 / 允许范围 / 禁止范围 / 测试 / 验收 / commit-push-pack-deploy 权限 / 状态`。

当前任务：初始化核验与需求确认。没有已批准的业务代码实施任务。

## 7. 测试与评审

建立 `REQ-ID → TASK-ID → TEST-ID → AC-ID` 对应关系。每个测试记录 subject commit、环境、命令、结果、失败/未覆盖项和证据位置。

按实际技术栈选择类型检查、构建、单元、契约、集成、关键流程和风险相关测试。没有运行条件时写 BLOCKED/NOT_RUN 并解释，不创建空套件冒充成功。

Review 记录：风险分级、设计/代码/兼容性/安全问题、严重度、文件位置、修复与复核结果。高风险/关键风险按标准要求独立复核。

当前测试与评审：NOT_RUN。

## 8. 验收

逐条记录 `AC-ID / 对应需求 / 验证方式 / 证据 / 结果 / 验收人 / 日期`，全部满足当前范围才接受。记录残余风险、负责人和处理期限；未完成不标记通过。

当前：PENDING。

## 9. 发布与生产验证

发布计划包括目标环境、已验收 commit、制品、配置名称、数据变更、执行者、授权、部署/回滚步骤、健康检查和观察窗口。运行结果与计划分开记录。

无部署的交付也要说明制品如何交给使用者以及验证方式。GitHub 合并、打包成功或创建 Release 都不能替代实际环境验证。

当前：未发布，部署/生产验证 NOT_RUN。

## 10. 维护与交接

记录运行监测和支持负责人、缺陷入口、恢复约定、迭代优先级。每次会话结束更新 CURRENT_STATUS 的完成项、停点、下一任务、阻塞、branch/commit 与证据；已有模块还需更新 Module STATUS。

## 11. 决策与待确认项

每项记录问题、影响、owner、决定或解除条件、证据；只对会实质影响当前结果的缺口询问用户。项目状态、设计和 GitHub 讨论出现差异时先修复记录。
