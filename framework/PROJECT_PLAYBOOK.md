# 项目开发手册 V0.1

本手册规定每个项目如何推进。项目具体内容集中在 `docs/PROJECT_PLAN.md`，详细内容增长后再拆分为专题文档；拆分时保留入口与链接。

## 每个阶段交什么

| 阶段 | 输入与主要工作 | 最小产物 | 进入下一步的条件 |
| --- | --- | --- | --- |
| 立项/需求 | 目标用户、问题、约束、成功指标 | 需求 ID、首版范围、不做事项、验收条件 | owner 确认范围；未知项明确，Spec 可审核 |
| 产品范围 | 已确认需求、优先级 | 角色、功能清单、核心规则、版本切分 | 没有影响首版实现的未决产品规则 |
| UX/用户流程 | 场景和角色 | 主流程、异常/空/无权限状态、页面清单 | 路径覆盖需求；无界面项目说明 N/A |
| UI/设计 | 已审 UX、品牌、终端 | 设计链接与版本、组件/响应式/状态说明 | 设计可实施；无视觉界面说明 N/A |
| 架构 | 范围、非功能约束、设计 | 技术选择理由、模块边界、依赖、数据流、风险 | medium 以上 Architecture Gate 通过 |
| 数据设计 | 数据所有权、一致性与保留要求 | 实体关系、约束、索引、变更/恢复方案 | 无数据库则说明 N/A；Migration 走对应风险审查 |
| API/契约 | 业务规则、边界、数据 | 输入输出、错误、权限、幂等/分页规则 | 消费方与实现方可据此工作；无接口说明 N/A |
| 任务拆解 | 已通过设计、依赖关系 | 原子任务、允许范围、验收、测试、Git 权限 | 每项任务有 owner、风险和可执行入口 |
| 开发 | 单项已批准任务 | 代码、必要文档、变更自检 | 范围内完成，Implementation 出口证据齐全 |
| 测试 | 需求/验收映射、实际代码 | 命令、环境、commit、正例/异常/回归结果 | 必需测试通过；未运行项不能写 PASS |
| 安全/评审 | 架构、变更、测试证据 | 权限/数据/依赖/失败恢复复核与问题清单 | 按风险关闭阻塞；high/critical 要求独立复核 |
| 验收 | 逐项结果与已知限制 | owner 的验收结论、剩余问题和责任人 | 满足本次范围，不能以合并 PR 代替业务验收 |
| 发布/上线 | 已验收 commit、环境与授权 | 制品、配置名、部署/回滚步骤、发布记录 | 执行已授权部署并完成健康检查与 Production Gate |
| 维护/交接 | 实际运行问题和迭代目标 | 缺陷/迭代 Issue、监控责任、CURRENT_STATUS | 新接手者可以从记录找到下一步 |

测试、安全与评审可以在前序阶段提前执行。表格是完整交付链，不要求等所有模块设计完才写任何代码；每个增量独立通过适用门禁。

## 阶段与门禁

Project stage 的 mode/status 遵循 `WORKFLOW.md`；Module 使用自身生命周期。任务拆解属于 Plan，验收与交接是 Agent Flow 的必要步骤，不额外发明 Module Gate。

Spec、Architecture、Implementation、Test、Security、Acceptance、Release 的准则来自 `.agent-project/gates.yaml`。高风险不能因为“首版很小”被降级；不适用项按事实写理由。复制模板只完成初始化，不会自动通过这些门禁。

## 能力选择

每个新项目填写能力表。至少评估身份/登录、角色权限、存储/OSS、配置与审计、媒体、通知、支付以及业务特有能力；每项记录 `采用 / 延后 / 不适用 / 待定`、原因、来源、风险、负责人、验证要求。

来源可以是已验证的本仓库模块、成熟外部组件、项目自有实现或待开发。记录实际版本/支持证据；没有实现时保持待开发。APF 的 Storage 规格可作为契约样例，不能作为已经可安装的 OSS SDK 包。

## 一个功能的日常循环

1. 用开发任务 Issue 明确需求、允许范围、禁止范围、验收和测试。
2. Codex 在确有设计缺口时分析；方案已经确定的任务直接交 Cursor。
3. Cursor 在专题分支实现，运行适用测试，更新当前状态。
4. 通过 PR 复核代码、测试、兼容性、风险和验收；Git 操作按当前任务授权执行。
5. 验收结果回写需求和任务。发布另记录具体 commit、环境和结果；每次交接保留下一步。

Issue 中的讨论允许改变方案，但最终决定必须写回对应需求/设计/状态文件；不能只保留在聊天中。

## 文档规模

初始只用一份项目计划承载各阶段有内容的记录。出现足够内容后，可拆为 `docs/requirements/`、`docs/design/`、`docs/architecture/`、`docs/testing/`、`docs/releases/` 等实际文件；目录不预建空壳。

模型和工具由 `.agent-project/agents.yaml` 指定，通用流程不依赖某个供应商。复制来的提示词可随项目配置调整；每个实际提示词第一行标注执行工具、模型和适用推理等级。
